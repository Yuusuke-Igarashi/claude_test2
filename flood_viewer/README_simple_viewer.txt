flood_viewer_simple_standalone.html の使い方
===========================================

車流（TomTom 交通統計）の異常リンクと XRAIN の降雨を、時刻スライダーで重ねて見るビューアです。
HTML 1 ファイルで動き、ファイル名は変えてかまいません（地図の背景に地理院タイルを使うため、インターネット接続が必要）。
tomtom_run.ipynb の output フォルダをそのまま読み込む前提で作ってあります（5. を参照）。

1. 読み込み
  - ファイルをダブルクリックで開く。
  - 「1. 車流（TomTom 交通統計）のフォルダ（必須）」: notebook の output フォルダ。*_network.geojson、baseline_speed.csv、
    event_speed.csv、baseline_count.csv、event_count.csv を読む。viewer.json があれば期間と閾値の既定値に、
    error.csv があれば判定の照合に使う。フォルダの代わりにファイルを個別に選んでもよい。
  - 「2. 降雨（XRAIN）のフォルダ（任意）」: rain_YYYYMMDD_HHMM.tif（15 分ごとの GeoTIFF）の入ったフォルダ。
    1 のフォルダの中に rain/ があれば省略できる。
  - 「読み込む」を押す。output フォルダにこの HTML を置いて http:// 経由で開いた場合は自動で読み込む
    （ネットワークは viewer.json の files.network に書かれた名前で読む）。

2. 画面
  - 上段: 再生／時刻／スライダー、対象リンク数と異常リンク数（L1〜L3）、⚙ 閾値、降雨のオン・オフ、
    カーソル位置の降雨強度。
  - 道路リンク: 対象外 = 灰、対象 = 黒、異常 = L1 橙・L2 赤・L3 暗い赤紫（番号が大きいほど強い落ち込み）。
  - リンクにマウスを重ねると、平時とイベント時の速度・台数の時系列グラフが出る（異常の区間は帯で示す）。
    クリックで固定、道路以外をクリックで解除。
  - 降雨: 道路の下に半透明で重ねる。色分けは気象庁の降水強度の凡例と同じ
    （1–5, 5–10, 10–20, 20–30, 30–50, 50–80, 80 mm/h 以上。1 mm/h 未満は透明）。
  - キー: ← → で 1 窓（15 分・30 分）移動、Space で再生／停止。

3. 判定（⚙ 閾値で変更できる）
  - 既定値は viewer.json の値（notebook と同じ閾値）。viewer.json が無いときは次の値:
    対象リンク: 平時の台数 ≥ 1 時間 10 台を窓の長さで換算（15 分窓 2.5、30 分窓 5） かつ 平時の速度 ≥ 10 km/h。
    比 = イベント時 ÷ 平時。L1: 速度比 ≤ 0.75 または 台数比 ≤ 0.75、L2: 同 0.60、L3: 同 0.50。
  - レベルごとに「または」「かつ」を選べる。「既定値に戻す」は上の既定値に戻す。
  - 裏取り: 対向リンクが同時刻に同レベル以上、または同じリンクが隣の窓（前後 15 分・30 分）も同レベル以上の
    ときだけ異常とする（チェックで外せる）。
  - 「欠測の扱い」のチェック: 当日の台数が 0 で速度が空欄の窓を速度 0 として判定し、グラフにも 0 で描く。
    外すと、速度が空欄の窓は速度比の条件を満たさない扱いになる（「または」のレベルは台数比だけで該当し得るが、
    「かつ」のレベルには該当しない）。既定は viewer.json の zero_speed_when_no_traffic の値、無ければオフ。
  - error.csv を読み込んだときは、画面の再計算との不一致セル数を閾値パネルに表示する。

4. 時間軸（期間）
  - 画面に時刻や日付を入力する所はない。期間は読み込んだデータだけから決まる。
  - 車流フォルダの viewer.json（notebook が TomTom ファイル名から読んだ期間の開始・時間数・窓の長さ）を使う。
    無ければ error_geojson/ の error_L1_YYYYMMDD_HHMM.geojson などのファイル名の最も早い窓、それも無ければ
    CSV の列順とネットワークファイル名の日付になる（この場合、期間が日付をまたぐときは正しく並ばない）。
  - 12:00 から翌 12:00 の 24 時間なら 12:00 → 23:30 → 00:00 → 11:30（30 分窓）の順に並び、時刻表示は
    日付をまたいだ先で翌日になる（例 08-14 00:30）。見出しに期間（例 冠水候補 2026-08-13 12:00〜08-14 12:00）が出る。
  - 窓の長さ（15 分・30 分）は CSV の時刻列から読み、台数の単位（台/30分）や裏取りの「前後 n 分」に反映する。
  - 期間がおかしいときは notebook 側で直す（viewer.json を作り直す）。
  - 降雨はこの日付に従う（日付をまたいだ時刻は翌日のファイル）。その日のファイルが無い時刻は
    「この時刻の降雨なし」と表示する（別の日の降雨は出さない）。

5. notebook（tomtom_run.ipynb）の出力との対応
  - 読むファイル: viewer.json、YYYYMMDD_network.geojson、baseline_speed.csv、event_speed.csv、baseline_count.csv、
    event_count.csv、error.csv（照合用）、error_geojson/（viewer.json が無いときの期間の予備）。
    error_links.csv、レベル別の CSV（error_level1〜3.csv）、flood_candidates.geojson / .gpkg はこのビューアでは使わない。
  - viewer.json には notebook のパラメータがそのまま入る。期間は TomTom ファイル名（*****_MMDD_0_HH_MM-HH_MM_*）から
    読んだ開始時刻・時間数・窓の長さ。閾値は notebook の既定では、平時 5 台/30 分以上 かつ 10 km/h 以上、
    L1: 速度比 ≤ 0.40 または 台数比 ≤ 0.40、L2: 速度比 ≤ 0.40 かつ 台数比 ≤ 0.40、L3: 速度比 ≤ 0.20 かつ 台数比 ≤ 0.20、
    裏取りあり。notebook 側で値を変えて実行し直せば、ビューアの既定値もそれに従う。
  - notebook は「当日の台数 0 で速度欠測」の窓を判定では速度 0 として扱い、event_speed.csv には空欄のまま書く。
    viewer.json の zero_speed_when_no_traffic が true なので「欠測の扱い」のチェックが既定でオンになり、同じ判定になる。
    チェックを外すと、そのような窓は「かつ」のレベルには該当しなくなる。
    （古い版の notebook は event_speed.csv に 0 を書き、viewer.json にこの項目が無い。その出力ではチェックの既定はオフで、
     付けても外しても結果は変わらない）
  - 画面の判定は notebook と同じ規則で再計算している。閾値が既定のままで不一致が出るときは、
    viewer.json・CSV・error.csv が別の実行のものになっていないか確認する。
